# Contracts, version 1

Frozen for the first implementation on 2026-11-17. JSON schemas are exported by `workevo schemas`; source models are authoritative. All records reject unknown fields, nonfinite numbers, invalid ranges and incompatible schema versions. Content identity is SHA-256 over sorted compact UTF-8 JSON with explicit nulls; skill revision hashes exclude no semantic fields. Parent revisions, instructions, parameters, context requirements and operator versions all contribute.

Workflows contain at most 64 uniquely named nodes, one entry, explicit terminals, a total step bound, and per-node visit bounds. A node has an operator/version, parameters, next destination and optional boolean-result branch. Node input is a copied JSON state; output becomes the next state. Branches inspect a named top-level boolean field; absent/nonboolean values fail rather than silently choose a branch. Only registered, trusted async operators execute. Operators receive no dataset labels or evaluator object. Unknown operators, dangling/unreachable nodes, node/terminal collisions, arbitrary source fields and missing exit paths are invalid. Cycles require explicit visit bounds and remain subject to the global step limit.

Operators are trusted application code, not a sandbox for untrusted functions. No eval, shell execution, generated imports or generated source is supported. Async callbacks must cooperate with cancellation and never block the event loop. Wall deadlines are checked before/after and around awaits; this cannot forcibly terminate malicious application code. Budget capabilities cannot promise an OS sandbox or exact billing where telemetry is unavailable.

A dataset contains exactly three nonempty partitions: development, validation, test. Case IDs are unique, template families are disjoint between partitions, and canonical duplicate inputs are rejected. A case owns an input and evaluator-only expected output; runner calls receive a copy of input only. The authored fixture is 24 cases, eight per partition, with distinct template IDs and disjoint values. It includes Unicode, identifier strings with leading zeros, missing names, aliases, malformed values, aliases in conflict and distractors. Two repeats per case can be requested; deterministic default is one.

Expected output is exactly `{id: string|null, name: string|null}`. Missing/null identifiers remain null; strings are trimmed and preserve leading zeros; integer IDs convert to decimal strings; other IDs become null. Name strings are trimmed; empty/nonstring names become null. Primary `id`/`name` keys take precedence over `identifier`/`display_name`, including explicit nulls. Extra fields are discarded. Labels are authored independently of runner operators. Schema-invalid output is a hard failure. Schema-valid wrong output lowers correctness. Seed already produces valid schema, but fails alias and trimming cases. Proposals add alias handling, then trimming, then a deliberately bad mutation as a retention regression check.

Trial identity includes study, candidate hash, split, case ID, repeat and attempt. Started attempts are durable before dispatch. A crashed pending attempt remains charged and becomes `interrupted` on explicit local resume. A replacement attempt consumes a new reservation. Completed evidence is reused only for the exact configuration/case/repeat. Selection requires the full exact case/repeat membership, same evaluator/dataset/runner/context hashes, and no unresolved trials for that candidate's evidence.

A study has one immutable configuration, per-study champion pointer, proposal cursor, persistent budget ledger and events. A process lease prevents two writers driving the same study concurrently; stale lease recovery is explicit and local. Each checkpoint is transactional. A candidate is stored before its execution. Decisions and champion compare-and-swap commit together; the pointer cannot reference partial evidence. Completed iterations and budget charges survive interruption. Token/cost reservations for unresolved provider calls are not refunded.

Limits include candidates, trials, operator calls, model calls, reserved/actual total tokens, micro-USD, validation looks, per-artifact bytes, steps, node visits, edit distance and absolute elapsed seconds from study creation (including downtime). Capabilities for model hard caps require a host-declared upper bound and actual post-call usage; unknown usage with requested hard caps is refused. Proposed/provider failures are still charged. Inputs/output/params are bounded JSON; context contents and private raw task payloads are absent from shareable reports by default.

Promotion is paired, deterministic: all schema/execution gates pass; correctness meets the configured floor; no per-case correctness regresses; aggregate quality improves by the configured margin, or exact quality ties with lower mean operator calls. Ties retain incumbent. Missing/partial/incompatible evidence yields `inconclusive`. Default margin is zero with a strict improvement requirement, floor zero, one repeat, six validation looks, six candidates and patience three. The seed must pass all hard gates on development and validation before it becomes incumbent. No eligible seed gives `no_valid_skill`.

A validation feedback request includes only the decision and aggregate reason. Proposers receive development inputs/outcomes and short hypotheses, never validation/test cases, labels or raw validation results. Final testing requires a frozen study and atomically marks a single test attempt begun; a resumed final test may fill missing exact trials, but a completed final report is immutable. Test outcomes never restart search for that study.

Pareto membership requires eligible, complete evidence under the identical comparison identity. Maximize quality; minimize mean calls, latency and optional measured monetary cost. Missing required metrics fail closed. A declared epsilon discretizes objectives into deterministic bins; nondominance is computed in bin coordinates. Archive capping is deterministic quality-first. Routing filters applicability and resource constraints before selecting by the caller's priority. It abstains if none qualifies.

Schema version 1 SQLite databases are created transactionally; unknown/newer user_version is rejected. Version 0 with existing user tables is not assumed migratable. Current version requires no data migration; release tests verify rejection and transactional initialization. Future migrations require fixtures and rollback tests before incrementing the version.


## Implemented refinements

`StudyConfig` records the exact Python source implementation hash. Reusing a study under changed implementation/operator/context/proposer identities is refused. Model usage annotations identify measured, estimated and unknown fields; unknown reservations remain charged. The prototype is compatible with Python 3.11–3.13 under the tested lockfile.

A seed can be supplied or retrieved with existing ancestry. With `generate_seed=True`, a task scaffold is recorded first; the proposer generates the initial executable skill before any case execution, within the same ledger. The generated skill must preserve task family, skill ID and context/permission boundaries. New seed generation may change the whole bounded workflow rather than obey the smaller mutation edit budget. Model-generated source remains unsupported.

The explicit global retry cap counts revisits to workflow nodes, alongside each node's visit bound and the total step/tool-call caps. Source-free reports and bundles are bounded local files written atomically. Import treats evidence as untrusted provenance and cannot promote a champion. Deployment operates without an evaluation dataset.


The persistence boundary independently verifies accepted promotions in the same transaction as the pointer update, using exact development/validation case-repeat keys pinned in the study. A low-level caller cannot promote an unscored revision merely by passing an accepted decision. Trial commits validate case/repeat identity. Empty, duplicate, unresolved or incompatible evidence cannot satisfy the gate.

Task specification is represented by the dataset/family, evaluator schema callable and registered-operator contract, rather than a separate TaskSpec class. Workflow nodes carry explicit operator versions and parameter schemas. Richer application input schemas remain host-owned; the core validates bounded JSON and the declared output evaluator.
